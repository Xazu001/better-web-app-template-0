# Aliases — rule

> Route types (`RouteLoaderArgs`, `RouteActionArgs`, `RouteServiceContext`) → `routes.md`. Server imports (`$/lib/*`, `$/services/*`), service structure → `server.md`.

## Definitions (in `tsconfig.cloudflare.json`)

Aliases are declared in the `compilerOptions.paths` field in `tsconfig.cloudflare.json` — this is the file read by TypeScript, build, and lint. There is no separate alias configuration file.

```jsonc
"paths": {
  "#/*": ["./app/*"],
  "$/*": ["./server/*"],
  "@/*": ["./shared/*"]
}
```

| Alias | Maps to      | Layer  |
| ----- | ------------ | ------ |
| `#/`  | `./app/*`    | App    |
| `$/`  | `./server/*` | Server |
| `@/`  | `./shared/*` | Shared |

The `include` field in `tsconfig.cloudflare.json` limits compilation to `app/**/*`, `server/**/*`, `shared/**/*`, `worker.ts`, and types generated by React Router (`.react-router/types/**/*`). `scripts/` is intentionally outside `include`.

## Dependency boundaries

| From     | Can import       | Cannot import |
| -------- | ---------------- | ------------- |
| `server` | `$/`, `@/`       | `#/`          |
| `app`    | `#/`, `@/`, `$/` | —             |
| `shared` | `@/`             | `#/`, `$/`    |

Dependency direction: `shared` (lowest layer) ← `server` ← `app` (highest layer). Imports flow only downward.

### Why

- **`shared` is a leaf** — it contains constants, enums, validators, and types used by both `server` and `app`. If `shared` imported `#/` or `$/`, it would create a cycle: a higher layer would depend on a lower one, and the lower one on the higher one. Therefore, only `@/` is allowed in `shared/` (and imports of external packages, e.g. `@hono/zod-openapi`).
- **`server` does not know the UI** — server code (services, D1, queues, mail) must be callable from `worker.ts` and from tests without loading the React layer. Importing `#/` would pull `app/` (components, hooks, stores) into the server bundle and break this contract. Therefore, `#/` is forbidden in `server/`.
- **`app` can reach into `server`** — routes call services (`BaseService`), read cookies (`$/lib/cookies`), and use decorators (`createRouteService`). This is the only allowed upward dependency and it is intentional.

### OK examples

In a file in `app/routes/` (highest layer — can do everything):

```ts
import { cookiesModify } from "$/lib/cookies";
import { type RouteLoaderArgs, createRouteService, dataMethod } from "$/lib/decorators";
import { BaseService } from "$/services/base";
import { SITE_URL } from "@/constants/site";
import { LoginSchema, Validator } from "@/validators";

import { data, redirect } from "react-router";
```

In a file in `server/services/` (intermediate layer — `$/` and `@/`):

```ts
import { CacheManager, QueueManager } from "$/cloudflare";
// relative within server/
import type { Database } from "$/core";
import { UserStatus } from "@/enums";

import { responses } from "../lib/response";

// shared — OK
```

In a file in `shared/validators/` (leaf — only `@/`):

```ts
import { USER_STATUS_VALUES } from "@/enums";
import { z } from "zod";
```

### FORBIDDEN examples

```ts
// FORBIDDEN in server/** — server cannot import app/
import { useRipple } from "#/lib/hooks";
import { Button } from "#/components/ui/button";

// FORBIDDEN in shared/** — shared is a leaf
import { BaseService } from "$/services/base";
import { cookiesModify } from "$/lib/cookies";
import { useRipple } from "#/lib/hooks";

// FORBIDDEN everywhere — use the alias, not relative paths across directories
import { BaseService } from "../../server/services/base";
import { SITE_NAME } from "../../shared/constants";
```

## Key rules

- **Always aliases** between `app`/`server`/`shared` directories — never `../../`. The alias is more readable and resilient to file relocation.
- **Within the same directory `./utils` is OK** — relative imports within a single module (e.g. `server/services/base.ts` → `../lib/response`) are more readable and indicate colocation.
- **`scripts/` lies outside `app`/`server`/`shared`**, so aliases do not reach there (it is not in `include` in `tsconfig.cloudflare.json`). Relative paths are used in scripts:

```ts
// scripts/stylelint-apply-order.ts
import { canonicalizeClasses, sortClasses } from "./tw-order.js";
```

When a script needs code from `shared/`, it imports it relatively: `../shared/constants`.

- `$/lib/cookies` — `cookiesModify` (and helpers from `cookies/helpers.ts`)
- `$/lib/crypto` — `hashPassword`, `verifyPassword`

- `$/services/base` — `BaseService` (base service class)

## Route types

`RouteLoaderArgs` / `RouteActionArgs` / `RouteServiceContext` are exported from `$/lib/decorators` (file `server/lib/decorators/route-service.ts`). Usage details in routes → `routes.md`.

## How to diagnose bad imports

- **`pnpm lint`** runs `oxlint` (configuration in `.oxlintrc.json`). The `import`, `typescript`, `react`, `unicorn`, `oxc` plugins are enabled.
- **Note:** in the current `.oxlintrc.json` configuration **there is no active rule enforcing layer boundaries** (neither `import/no-restricted-paths` nor a boundary-type rule). `oxlint` will catch, among other things, unused imports, `no-undef`, type errors via the `typescript` plugin, but cross-layer import (`#/` in `server/` or `$/` in `shared/`) **is not currently blocked automatically**.
- Dependency boundaries are enforced by **convention and review** and indirectly by the build: if `server/` imports `#/`, TypeScript may resolve the path, but the Cloudflare Worker bundle should not pull React code on the server side — watch the bundle size and errors like "cannot use DOM on server".
- **Quick manual audit:**

```bash
# FORBIDDEN: #/ in server/
grep -rn "from [\"']#/" server/

# FORBIDDEN: #/ or $/ in shared/
grep -rn "from [\"'][#$]/" shared/

# FORBIDDEN: relative paths across the main trio of directories
grep -rn "from [\"']\.\./\.\./\(app\|server\|shared\)/" app server shared
```

- To automatically enforce boundaries in the future, you can add the `import/no-restricted-paths` rule to `.oxlintrc.json` (when `oxlint` supports it) with a `zones` mapping for `#/`, `$/`, `@/`.

## Prohibitions (summary)

- `../server/...` when `$/` exists — use the alias.
- `../shared/...` when `@/` exists — use the alias.
- `#/` in `server/` code — server does not depend on app.
- `#/` or `$/` in `shared/` — shared is a leaf.
- `../../` between `app`/`server`/`shared` — always use an alias.
